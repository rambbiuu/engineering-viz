Spreading, processing gain and the near-far problem

Code-division multiple access lets every handset talk on the whole band at once. Each multiplies its data by a fast code, and the base station multiplies by the same code to dig the signal back out.

New to this? Start with the link budget for what a noise floor is, then cellular reuse for the alternative that buys capacity with geometry instead.

An everyday picture. Everyone talks at once in different languages — you follow yours by language, not volume, until someone beside you shouts; that shout is the near-far problem.

Fixed assumptions behind the numbers

Data rate is held at 9.6 kbit/s, the IS-95 vocoder rate, so the chip rate is the code length times 9.6 kbit/s and a 128-chip code lands on the real 1.2288 Mchip/s. The required energy-per-bit to noise-density ratio is 7 dB, voice activity is 0.4, other-cell interference is 0.6 of own-cell, and the path-loss exponent is 4. Power control moves the transmitter in 1 dB steps and the channel carries Rayleigh fading at a 50 Hz Doppler, which is roughly 60 km/h at 900 MHz.

Three things live in these sliders. Spreading buys interference rejection at a fixed exchange rate: every doubling of the code length adds 3 dB to the processing gain and 3 dB to the ratio the correlator delivers, which is why a chip rate is quoted alongside a data rate in every code-division system. The whole band is reused in every cell, so capacity is set not by geometry but by how much interference the correlator can survive — push the user count past the number in the card and the link stops closing for everybody at once, which is what a soft capacity limit feels like. And processing gain is a ratio, not a level: drag the near-far imbalance up with power control off and watch the ratio after despreading fall exactly as fast as the ratio before it, because 24 dB of gain cannot rescue a signal 60 dB down.

Where this model is simplified, and it is simplified in five places. Power control is the real closed loop — a one-bit up or down command, 1 dB per step, at the rate you select — run over three seconds against a Clarke sum-of-sinusoids Rayleigh channel with a 50 Hz Doppler, and the residual error you see is measured from that simulation rather than assumed. But the fading has one tap and no shadowing, the loop has no measurement error and no feedback delay, and a real loop has both, so the residual here is optimistic. Walsh rows are treated as perfectly chip-aligned, which is true on the downlink from one base station and false on the uplink drawn in section 1; that is why the interference from other users vanishes in Walsh mode and does not in PN mode. The interference each PN user contributes is measured from the actual cross-correlations of the generated m-sequence, averaged over 64 bits, so it lands within about a decibel of the textbook Gp rather than exactly on it. The capacity card assumes perfect power control and equal rates for everyone. And the honest ceiling stated in every course note applies here too: closed-loop power control at 800 Hz for IS-95 or 1500 Hz for WCDMA tracks path loss and shadowing, but it cannot compensate for fast Rayleigh fading — set the imbalance to zero, switch the rate between 2 Hz, 800 Hz and 1500 Hz, and read the residual error printed on section 1. It never reaches zero.

1 · Two handsets, one base station — both transmit at once, on the same frequency

  • blue is the far handset — the one we are trying to receive.
  • orange is the near handset, close to the mast.
  • light blue bars are the other users, all landing in the same band.
  • Bar height is received power at the base station, in decibels against the level the far user should arrive at.

2 · Data bit, chip sequence, spread product — s(t) = d(t) · c(t), one multiplication

  • blue is the data d(t): two bits, each lasting Tb.
  • orange is the code c(t): the chip sequence, running Tb/Tc times faster.
  • yellow is the product s(t). Where the data bit is +1 it copies the code; where the bit is −1 it inverts it.

3 · The spectrum, before and after spreading — same power, spread over Gp times the bandwidth

  • blue is the data before spreading: tall, and only a few kilohertz wide.
  • orange is the same power after spreading, flattened across the whole chip bandwidth.
  • The dashed line is the floor of noise plus every other user's signal. When orange sits below it, the transmission is invisible to anything that does not know the code.

4 · The correlator, integrating over one bit — right code climbs, wrong code stays at zero

  • The top panel is what actually arrives at the antenna: every user's chips added together, plus noise. Nothing in it looks like data.
  • green is the running integral z = (1/Tb)∫r(t)c(t)dt with the far user's own code. It walks towards the transmitted bit, ±1.
  • red is the same integral taken with a code nobody is using. It has nothing to lock onto, so it stays near zero.

    Code properties, checked against the sequences this page generated
      Glossary
      Chip
      One symbol of the spreading code. Chips are much shorter than data bits: Tc against Tb.
      Spreading
      Multiplying the data by the code, s(t) = d(t)c(t). It widens the bandwidth from the data rate to the chip rate without adding power.
      Despreading
      Multiplying the received signal by the same code again and averaging over one bit. The wanted signal collapses back to narrowband; everything else stays spread.
      Processing gain Gp
      The bandwidth expansion ratio, Rc/Rb = Tb/Tc. In decibels it is 10·log10 of that ratio, and it is how many decibels the correlator adds to the signal-to-interference ratio.
      Correlator
      The circuit that computes z = (1/Tb)∫r(t)c(t)dt over one bit period. Its output is the despread symbol.
      Cross-correlation
      The average product of two codes, chip by chip. Zero means the two signals do not disturb each other at all.
      Walsh–Hadamard code
      Rows of a matrix built by H2n = [[Hn, Hn], [Hn, −Hn]]. Any two distinct rows have exactly zero cross-correlation, provided they arrive perfectly aligned.
      PN m-sequence
      A pseudo-noise sequence from a shift register with feedback, of period 2m−1. Its autocorrelation is 1 at zero lag and exactly −1/L at every other lag, which is what makes it look like noise.
      Near-far problem
      A handset close to the base station arrives far stronger than a distant one. Because both occupy the same band, the strong one drowns the weak one no matter what codes they use.
      Power control
      The base station tells each handset to raise or lower its power, one bit and 1 dB per command. GSM does this at 2 Hz, IS-95 at 800 Hz, WCDMA at 1500 Hz.
      SIR
      Signal-to-interference ratio: wanted power divided by everything else. Quoted before despreading it is measured at chip level and is usually negative; after despreading it is the ratio the decision circuit sees.
      Eb/N0
      Energy per data bit divided by noise-plus-interference power density. It is the same number as the SIR after despreading, and it is what a modem specification quotes.
      Pole capacity
      The user count at which interference alone consumes the whole link budget: N = 1 + (W/R)/(Eb/N0)req. No amount of transmit power gets past it.
      Rayleigh fading
      The rapid level swings caused by reflections adding and cancelling as the handset moves. Deep fades come and go in milliseconds.
      Decibel (dB)
      A ratio on a logarithmic scale: 10·log10 of a power ratio. Ten decibels is ten times the power, 3 dB is roughly double.
